## 为什么要做

nanobot 目前只能在单次对话中临时使用附件，无法持久保存用户提供的知识，也无法在后续对话中稳定检索。我们需要增加一套私有、本地优先的 RAG 能力，让用户能通过各聊天渠道建立容量受控的个人知识库，同时避免把完整文档、向量、查询内容或重排候选发送给第三方服务。

## 变更内容

- 在所有能提供可信发送者身份和会话类型的渠道私聊中，新增 `/rag add`、`/rag status`、`/rag list`、`/rag delete` 和 `/rag ask` 命令。
- 为支持的 PDF、OOXML 和文本格式增加异步、可恢复的文档入库流程，包括结构化切片、重复检测和可配置的用户配额；第一版不支持 OCR。
- 增加 `search_knowledge_base` Agent 工具，由服务端强制限定在当前 `(channel, sender_id)` 对应的私有知识库内。
- 增加面向中英文及中英混合内容的 Hybrid 检索：BM25 关键词检索、本地 Dense Embedding、RRF 融合、本地 Cross-Encoder 重排、证据阈值和来源引用。
- 增加基于 ONNX 的本地 Embedding 与 Reranker，提供跨平台 CPU 基线，并在 Apple、NVIDIA、Intel 和 Windows 兼容硬件上通过正确性校验与本机基准测试自动选择加速方案。
- 增加结构化 RAG 进度事件，覆盖查询、入库、删除、模型准备、硬件选择、完成、降级和失败。
- 将 RAG 依赖和配置设计为可选项；未安装或未启用 RAG 时，不改变现有 nanobot 行为。
- 第一版只提供互相独立的私人知识库；共享或群组知识库、跨渠道身份关联、OCR、远程 Embedding 和远程 Reranker 均不在范围内。

## 能力范围

### 新增能力

- `private-rag-library`：私人主体身份、私聊授权、显式文档入库、支持格式、配额、去重、生命周期命令、持久化任务、删除和故障恢复。
- `private-rag-retrieval`：Agent 与命令查询入口、中英文 Hybrid 检索、融合、重排、证据筛选、引用、无证据处理和检索降级披露。
- `local-rag-inference`：固定版本的本地 Embedding 与 Reranker、CPU 跨平台支持、模型供应链安全、硬件探测、基于实测的自动加速、Profile 兼容性和安全回退。
- `rag-progress-events`：结构化、隐私安全、限频的进度事件，以及 WebUI、可编辑消息渠道和纯文本渠道的展示行为。

### 修改现有能力

无。仓库当前没有需要由本变更修改其需求的既有 OpenSpec 能力。

## 影响范围

- 新增可选的 `nanobot/rag/` 子系统和 `rag` 配置组。
- 扩展命令路由、Agent 工具发现、类型化出站事件、渠道私聊能力报告和 WebUI 进度展示。
- 扩展现有文档提取工具，使其保留结构化位置并为 RAG 提供失败即关闭的安全语义。
- 新增可选的本地推理、分词、向量索引和模型下载依赖；未安装或未启用 RAG 时不影响基础安装。
- 新增按主体隔离的 SQLite 与 HNSW 存储，以及全局共享、版本固定的本地模型缓存。
- 新增跨平台测试、检索评测集、恢复测试和可选的真实模型硬件加速冒烟测试。

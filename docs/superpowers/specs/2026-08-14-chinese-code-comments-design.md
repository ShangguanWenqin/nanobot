# nanobot 主体代码中文注释设计

## 目标

基于当前 `main` 分支，为 nanobot 的 Python 后端和 React/TypeScript WebUI 运行时代码增加适合初学者阅读的中文教学注释。注释既要解释代码各部分如何工作，也要解释可从代码、架构文档和调用关系中验证的设计原因。

所有工作在 `codex/chinese-code-comments` 隔离分支中完成，不修改 `main` 分支。

## 范围

覆盖：

- `nanobot/` 下具有实际运行逻辑的 Python 源码；
- `webui/src/` 下具有实际运行逻辑的 TypeScript 和 TSX 源码；
- 后端与前端之间的 REST、WebSocket、会话、状态和配置衔接代码。

排除：

- 测试代码；
- `__pycache__`、构建产物和自动生成文件；
- 空 `__init__.py`；
- 仅包含导出、类型转发或常量搬运且没有独立业务逻辑的文件；
- 明显由 UI 工具生成、没有 nanobot 业务逻辑的基础组件。

最终提供覆盖清单和排除清单，使每个候选运行时代码文件都有明确处理状态。

## 全局理解优先

分批提交只用于控制审查规模，不能把项目理解割裂为局部文件理解。开始批量注释前，先建立全局代码认知地图，至少包含：

- CLI、Python SDK、外部聊天平台和 WebUI 等入口；
- Gateway、Channel、MessageBus、AgentLoop 和 AgentRunner 的主消息链路；
- Provider、Tool、MCP、子代理与模型调用循环；
- Session、Memory、Goal、Cron、自动化和本地触发器的状态关系；
- 配置加载、路径解析、工作区作用域和运行时上下文；
- 工作区限制、SSRF、Shell 沙箱、配对鉴权等安全边界；
- WebUI 经 REST/WebSocket 与 Python Gateway 交换会话、运行状态和设置的过程；
- Provider、Channel、Tool、Skill 与 Plugin 的发现、注册和生命周期。

全局认知地图应由实际入口、导入关系、构造过程、协议类型和调用链共同验证。现有架构文档用于辅助理解；若文档与实现不一致，以当前代码为准。不得猜测无法验证的设计动机。

## 注释标准

注释采用四层结构：

1. 模块层：说明文件职责、调用方、依赖方以及它在整个系统中的位置。
2. 类型与接口层：说明主要类、数据结构、函数、React 组件和 Hook 的输入、输出、状态归属与生命周期。
3. 流程层：解释异步循环、状态转换、重试、并发、上下文压缩、流式传输和协议转换的执行顺序及原因。
4. 边界层：解释安全约束、持久化一致性、兼容逻辑、Provider/Channel 差异和浏览器重连等不能随意简化的约束。

具体规则：

- 注释解释意图、上下文和取舍，不逐行复述语法；
- 使用初学者能理解的中文，必要术语首次出现时附英文名；
- 保留已有英文 docstring 和代码，不修改其内容；
- Python 只新增 `#` 注释，不新增或修改 docstring，因为 docstring 会进入运行时 `__doc__`；
- TypeScript/TSX 只新增 `//`、`/* ... */` 或 JSDoc 注释；
- 不修改函数签名、字符串、控制流、导入、公开 API 或格式化；
- 对无法确认的设计原因，只描述可验证的职责与调用关系。

## 实施批次

1. 基础模型：配置、路径、运行时上下文、消息事件与总线。
2. 核心执行：AgentLoop、AgentRunner、上下文构建、Hook、投递与模型运行时。
3. 状态系统：Session、Memory、Goal、Cron、自动化与本地触发器。
4. 工具系统：注册发现、文件、Shell、Web、MCP、子代理、长任务及媒体工具。
5. Provider 系统：公共协议、注册与工厂、模型适配、流式响应及回退策略。
6. Channel 系统：公共接口、发现与管理，以及各平台适配器。
7. 服务入口：CLI、Python SDK、Gateway、OpenAI 兼容 API 和 WebUI 后端服务。
8. WebUI 基础层：类型、客户端协议、API、运行时、Context 与 Hooks。
9. WebUI 功能层：会话、消息流、工作台、设置、自动化、技能和渠道插件组件。
10. 全局一致性复核：术语、交叉引用、遗漏文件和注释正确性。

每一批都必须基于同一份全局认知地图说明模块在系统中的位置，并以独立提交保存，方便审查和回退。

## 验收方式

按用户要求，不运行测试、类型检查或构建。验收重点是证明源码差异只有注释：

- Python：移除注释 token 后比较修改前后 token 序列；
- TypeScript/TSX：使用能够区分字符串、模板字面量和正则表达式的解析方式移除注释后比较源码；
- 检查 Git 差异，确认没有删除或修改已有非注释内容；
- 检查新增注释是否与全局调用关系一致，是否避免无依据的设计动机；
- 输出覆盖清单、排除清单和各批次提交摘要。

验证脚本本身不得改写源码，也不得用简单正则表达式错误处理字符串中的注释符号。
